# PRD：こもれび予約

| 項目 | 内容 |
|---|---|
| バージョン | v0.2 |
| 更新日 | 2026-09-10 |

## 1. 何を作るか（1段落）

個人経営の美容室「ヘアサロン こもれび」（スタイリスト2名）の予約受付を、電話と紙の台帳からスマホで受け付ける形に置き換える。いまは施術中に電話を取れず予約を逃し、台帳の書き間違いで二重予約も起きている。お客さんは24時間いつでも空いている日時を見て予約・変更・取り消しができ、店側は1画面で今日と明日の予約を確かめられるようにする。

## 2. 使う人

- お客さん（主な利用者）: スマホで予約ページを開き、メニューと日時を選んで予約する。最初にやるのは「空いている日時を見る」こと（会員登録は要らない）。
- 店主（運営者・1人）: 管理画面にログインし、営業日・休憩時間・メニューを設定する。毎朝、今日の予約一覧を見る。
- スタイリスト（店主以外の1名）: 自分が担当する予約を見るだけ。設定は変えない。

## 3. スコープ

### 3.1 やること（機能一覧）

| ID | 機能 | 説明 | 優先度 |
|---|---|---|---|
| A-1 | 空き枠の表示 | メニューの所要時間・営業時間・入っている予約から、予約できる日時を2週間先まで出す | Must |
| A-2 | 予約の受付 | 名前・電話番号・メールアドレスで予約を確定し、確認メールを送る | Must |
| A-3 | 予約の変更・取り消し | 確認メールのリンクから、来店前日の18時まで変更・取り消しができる | Must |
| A-4 | 店側の予約一覧 | 今日・明日の予約を担当者別に一覧する。電話で受けた予約を手で追加できる | Must |
| A-5 | 営業日とメニューの設定 | 定休日・臨時休業・休憩時間と、メニュー（名前・所要時間・料金）を店主が変える | Must |
| A-6 | 前日のお知らせ | 来店前日の10時に、お客さんへお知らせメールを送る | Should |

ID は A-1, A-2… の連番（消した番号は使い回さない）。`tasks/BACKLOG.md` の「参照: PRD A-1」と、`docs/requirements/` の各文書から指される。
機能は3〜7個を目安に、Must（最初の版に必須）か Should（あると良い）を付ける。何も書かずに `/docdd:add-task` と打つと、Must の行をまとめて起票する。

### 3.2 やらないこと（最初の版では作らない）

- オンライン決済（料金は来店時に店で払う）
- お客さんの会員登録・ポイント
- 複数店舗の管理
- 指名料の計算と売上の集計

### 3.3 主な画面（ゲームならシーン）と利用者の流れ

1. お客さん（予約）: 予約ページ → メニューを選ぶ → 空き枠カレンダーで日時を選ぶ → 名前・電話番号・メールアドレスを入れて確定 → 確認メールが届く。
2. お客さん（変更）: 確認メールのリンク → 予約の詳細 → 日時を選び直す、または取り消す。
3. 店主（毎朝）: ログイン → 今日の予約一覧（担当者別）→ 電話で受けた予約を手で追加する。
4. 店主（設定）: 設定画面 → 営業日カレンダーに臨時休業を入れる → メニューの所要時間・料金を直す。

## 4. 料金・上限（従量課金があるとき）

従量課金（AI・外部 API など、使った分だけ費用が出るもの）が無ければ、この節ごと削除してよい。

| 料金・上限 | 値 | 根拠 |
|---|---|---|
| お客さんの利用料 | 無料 | 集客のための道具。お客さんが払うのは来店時の施術代だけ |
| メールの月間送信数の上限 | 月3,000通 | 予約は1日最大20件 × 営業25日 × 1件あたり最大4通（確認・変更・取り消し・前日のお知らせ）＝月2,000通。余裕を見て3,000通。メール送信サービスの無料枠に収まる |
| 上限に達したとき | その月は前日のお知らせ（A-6）だけを止め、確認メールは送り続ける。管理画面に「今月のメール送信数が上限に達しました」と出す | 予約の確定を知らせる確認メールは止めない |

## 5. 非機能（守りたい性質）

- 黙って壊れない／原因が辿れる／手順を記憶に依存させない／費用が見える／判断はまとめて求める（`AGENTS.md` の5原則）
- 二重予約を作らない（同じ担当者・同じ時間帯に2件目が入りそうなら、後から来た方を「その時間は埋まりました」と断る）
- 確認メールが送れなかった予約は、管理画面の一覧に「確認メール未送信」と出す（送れなかったことを黙って捨てない）
