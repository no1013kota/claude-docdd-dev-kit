# verify-integration の落とし穴（症状 → 見る場所 → 対策）

`SKILL.md` の「見落としやすい3点」の詳しい版。当てはまる症状が出たときだけ読む。このプロジェクトに無い機能（外部 API・AI など）の行は飛ばす。

| 症状 | 見る場所 | 対策 |
|---|---|---|
| API（DB クライアントライブラリ経由）だけが `permission denied` や内部エラーで落ちる。管理者権限で DB に直結するテストは緑 | サーバー側が使うロール（特権ロールを含む）のテーブル権限（GRANT）と既定権限。モックしたテストでは見えない | ロール権限を明示的に検査するテストを足す。テーブルを追加したら既定権限まで確かめる |
| 中核ロジックのテストは全部緑なのに、実際の API 呼び出しで壊れる | 依存注入で渡している本番実装（実 DB クエリ・外部呼び出し） | サーバー側の処理そのものを実 DB で叩くテストを足す（セッションだけモックし、DB クエリは実際に走らせる） |
| 外部 API が 400 を返す（必須パラメータの欠落） | 受理されるかの検査 | 受理されるかの検査を回す。リクエストの組み立てを相手の公式ドキュメントと照らす |
| 外部 API が 400 を返す（出力の形の指定〔schema〕が相手の要件を満たさない） | 受理されるかの検査 | 受理されるかの検査を回し、schema を相手の要件に合わせる |
| 200 は返るのに、応答の前置き文のせいで JSON の検証が落ちる | 実物で1周だけが見える（受理されるかの検査は緑になる） | 実物で1周を回し、応答から JSON を取り出す処理を実物の応答で確かめる |
| 200 は返るのに、字数上限で全件が捨てられ、結果が常に0件 | 実物で1周だけが見える | 実物で1周で、最終成果物の件数と中身まで見る |
| DB を起動していないのに統合テストが緑 | テスト結果の skip 数 | DB 未接続なら fail する形で回す。必須の実 DB テストに skip があれば合格にしない |
| ホスト型の開発専用 DB で、前回の実行や別のテストのデータとぶつかって落ちる | テストデータの ID・一意制約・後片付けの結果 | 実行ごとの一意 ID で作り、今回作った分だけ消す。DB 全体の reset・truncate では解決しない |
