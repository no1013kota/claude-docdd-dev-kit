# ui-polish：画面の実装と仕上げ

既存のデザインのしくみ（部品・色や余白の決まり）を守って実装し、**実ブラウザで完成状態まで**確認する。実装だけで完了にしない。

## 手順

**最初に（Web の門）**: `AGENTS.md`「検証コマンド」表の『開発サーバー起動』行が「無い」なら（Web の画面が無いプロジェクト。例: Unity・Godot のゲーム、ネイティブアプリ）、このスキルは使わない。「該当なし」と報告して止まる（画面の確認は変更影響表の「画面・操作（Web 以外）」行）。

0. **道具を確かめる** — `playwright-cli --version`。通らなければ `npx --no-install playwright cli --help`（出力に `playwright-cli` を含む行があれば `npx playwright cli` で代用。終了コードでは決めない。古い Playwright は、その行の無いヘルプを出して 0 で終わる）。どちらも無ければ、下の§検証の「画面幅」のスクショは**探索的確認**（ブラウザの幅を変えて目で見る、または運営者に見てもらう）で行い、報告に「playwright-cli が無いため探索的確認」と明記する。インストールは運営者が望んだときだけ（`/docdd:playwright-cli` の「インストール」）。
1. **正本と既存を読む**
   - 仕様: 該当画面の要件と、関連する API の要件（`docs/PRD.md`・`docs/requirements/`・運営者が `docs/` に置いたそのほかの仕様書。タスクから来たなら、その「参照:」の節）
   - 既存: 対象の画面（ルート）・親レイアウト・共通 UI 部品のディレクトリ・グローバル CSS（デザイントークン〔色・余白などの共通の値〕の定義）・UI ライブラリの設定ファイル（例: shadcn/ui を使っていれば `components.json`）
   - **既存コンポーネントとデザイントークンを最優先。任意値を増やさない。** 新規部品が要るときは、使っている UI ライブラリの部品を先に探してから作る（例: shadcn/ui を使っていれば shadcn MCP でレジストリを検索）。
2. **方針を一言で決める** — 目的・主利用者・最優先アクション・情報階層。新規画面は見た目の方向を1つ選び、既存画面の更新は現行とのそろい方を優先。
3. **実装する** — 使っているフレームワーク・スタイリング・UI ライブラリの既存構成（ルーティング・サーバー側と画面側の境界を含む）に従う。
4. **実ブラウザで検証する**（下の§検証）
5. **docs 同期** — `/docdd:doc-sync` を実行する（`/docdd:dev-loop`・`/docdd:refactor`・`/docdd:speed-up`・`/docdd:security-audit` の中で使ったときは、呼んだ側が最後に回すので飛ばす）。
6. **報告** — 方針／再利用・追加した部品とトークン／確認した幅・テーマ・状態（探索的確認ならその旨）／修正点／未解消事項。**未解消があれば完了扱いにしない。**

## 実装の決まり

| 対象 | 決まり |
|---|---|
| 色・余白・角丸・影 | CSS 変数か既存ユーティリティを使う（直値を書かない） |
| 状態 | hover / focus-visible / disabled / loading / empty / error / success を該当分すべて |
| アクセシビリティ | 主要導線は WCAG 2.2 AA（キーボード・明瞭な focus・label・色以外の状態表現） |
| モーション | `prefers-reduced-motion` を尊重 |
| 仕様変更 | 画面挙動を変えたら**同じ作業単位で** `docs/` の正本を更新 |

## 操作結果の通知

- 通知（トーストなど、操作の結果を知らせる表示）の決まりが `docs/` の仕様書（`docs/requirements/` など）にあれば、それに従う。
- 無ければ、既存の画面の出し方に合わせる。出し方の共通化は `tasks/BACKLOG.md` の「要決定」へ積み（書式は運用ルールの見本）、この作業では仕組みを作らない。
- 成功も無言で終わらせない（`AGENTS.md` の原則「黙って壊れない」）。出し方を移すときの注意は `references/pitfalls.md`。

## 検証（実ブラウザ）

| 項目 | やること |
|---|---|
| 起動 | `AGENTS.md`「検証コマンド」表の『開発サーバー起動』行で起動する（行が「無い」か未記入なら、起動方法を推測で決めず理由を報告する）。OAuth など外部サービスが `localhost` を許可しない場合は **`http://127.0.0.1:<ポート>`** で開く（ホットリロードの許可オリジンも、開発サーバーの設定で同じホストに合わせる。Vite・SvelteKit・Astro・Nuxt の開発サーバーは既定で localhost だけで待ち受けるので、`--host 127.0.0.1` を付けて起動する） |
| ランタイム | ブラウザのコンソールと開発サーバーのログで、実行時・ビルド・Hydration（サーバーで作った HTML と画面側の食い違い）のエラーを見る（例: Next.js DevTools MCP を使っていれば、それでも確かめる） |
| 認証必須画面 | テストユーザーでログインして開く（ログイン状態の保存は `/docdd:playwright-cli` の「保存先」に従う） |
| 画面幅 | playwright-cli で Desktop 1440 / Tablet 768 / Mobile 390 のスクショ（playwright-cli が無ければ探索的確認と明記） |
| 実データ | **本物のデータを載せて描画を確認**（画像・表・グラフなど、外部から取得したり生成したりして表示するもの）。要素の存在ではなく実際に読み込めたこと（画像なら `naturalWidth>0`）。CSP（読み込み許可の設定）違反・署名 URL の失効・デコード失敗は実物でしか出ない |
| 潰すもの | 横スクロール・重なり・文字切れ・focus/label 欠落・色だけに頼った状態表示・コンソールエラー・レイアウトシフト（読み込み中の表示のずれ） |

修正したら同条件で再確認する。**スクショ／trace はコミットしない**（置き場は `/docdd:playwright-cli` の「保存先」）。
