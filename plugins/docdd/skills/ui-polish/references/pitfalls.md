# ui-polish の落とし穴（症状 → 見る場所 → 対策）

当てはまる症状が出たときだけ読む。このプロジェクトに無い仕組み（トースト・OAuth など）の行は飛ばす。

| 症状 | 見る場所 | 対策 |
|---|---|---|
| 通知を呼んでいるのに何も出ない（エラーも出ない） | 通知の仕組みの初期化（Provider など）の外で呼んでいないか。仕組みによっては、初期化の外で呼ぶと例外を投げずに何もしない | 出し方を移した画面ごとに、E2E で「実際に出る」テストを1件足し、呼び出しを消すと落ちることを確かめる |
| 同じ通知が2か所に出る、またはどこにも出ない | 画面内の古いメッセージ表示と、新しい通知の呼び出し | 古い表示を消すのと新しい通知を足すのを、同じコミットで行う |
| 入力エラーやボタン付きの案内まで通知（トースト）にして、見落とされる | 通知の決まり（`docs/requirements/`） | 入力検証・ボタンを伴う案内・恒常表示（画面の状態）は、通知ではなく画面内に出す |
| 別オリジン（別のドメイン）から読み込む画像が、ローカルでは必ず表示されない | ブラウザのコンソールの CSP 違反／CSP の `img-src` | 許可する読み込み先を設定に足し、実データを描画して `naturalWidth>0` を確かめる |
| OAuth などのログインがローカルでだけ失敗する | 外部サービス側の許可 URL に `localhost` が無い | `http://127.0.0.1:<ポート>` で開き、開発サーバーの許可オリジンも同じホストに合わせる |
