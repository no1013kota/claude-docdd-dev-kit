# 控えと戻し方

何の控えがあるか、どう戻すか、戻せたことを最後に確かめたのはいつかを、この 1 か所に書いておく。
`AGENTS.md`「反映コマンド」表が持つのは、控えを**取る**コマンド（『本番 DB のバックアップ』行）と、公開した**版**を戻す手順（『戻し方』行）の 2 つだけ。
**控えから利用者のデータを戻す手順の正本はこの文書**（§3）。

## 1. 何を守るか

| 守るもの | 控え | 戻し方 |
|---|---|---|
| コード | git（リモートへ push してある） | §4 |
| 利用者のデータ | 『本番 DB のバックアップ』行 | §3 |
| 利用者が上げたファイル（画像・添付） | 無い | 無い |
| 外部サービス側の設定 | 無い | 無い |

- 「守るもの」はこのプロジェクトに合わせて書き換える（DB を使わないなら、保存データ・セーブデータの置き場所を書く）。**控えや戻し方があるものは「無い」を実際の中身に書き換える。**
- **控えが無いものは「無い」と書いて残す。** DB の控えには、ふつう上げたファイルの実体と外部サービス側の設定は入らない。何が戻り、何が戻らないかを、ここで分かるようにしておく。

## 2. 置き場所

- リポジトリの外に置く。git には入れない（private のリポジトリでも）。
- 中身は利用者の個人情報なので、公開フォルダ・共有リンクへ置かない。
- 手元のほかに、もう 1 か所（外付けドライブ・クラウド同期）を決めて書く。
- 残す本数と、古いものをどうするかを書く。

置き場所: {{控えの置き場所（リポジトリの外。例: 外付けドライブ／クラウド同期フォルダ）}}

## 3. データを戻す

1. **本番ではない空の戻し先**を用意する。
2. 控えを戻す。**このプロジェクトでの手順をここに書く。**
3. 元と突き合わせる。期待する数値はこの文書に書かず（増減するため）、控えを取った側で同じ数え方をして、同じ数になることを見る（例: 表の数、初期データの件数、最新の 1 件の中身）。
4. 無視してよいエラー（権限まわりなど）が出たら、何を無視したかを §5 の行に書く。

**本番へ戻すのは、運営者の指示があるときだけ**（Claude は自分の判断で本番へ戻さない）。

## 4. 公開した版を戻す

| したいこと | 戻し方 |
|---|---|
| 公開した版を前の版へ戻す | `AGENTS.md`「反映コマンド」表の『戻し方』行（`/docdd:release` が、運営者の「はい」を得てから実行する） |
| 利用者のデータを控えから戻す | §3 |
| 外部への送信・課金を止める | 止める設定値と、その戻し方を書く（無ければ「無い」） |

**版を戻すのと DB を戻すのは別の作業。** migration（DB の構造変更）を含む反映を戻すときは、§3 も要るかを必ず確かめる。
